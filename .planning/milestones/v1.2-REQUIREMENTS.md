# Requirements: v1.2 Connector Label Writing

## Scope

This milestone extends AFFiNE Canvas Power Tools so operators can add or update labels on existing connector arrows through a review-first, gated live-apply workflow.

## Non-Goals

- Do not create a new diagram layout system.
- Do not move cards, resize cards, relink connectors, or rebuild connectors while applying labels.
- Do not infer labels from a model inside the CLI.
- Do not send live AFFiNE mutations without the existing workspace/doc/backup/confirmation gates.

## Requirements

| ID | Requirement | Acceptance Evidence |
| --- | --- | --- |
| LABEL-01 | Search and model output must include connector label text and label style when present on `affine:surface` connector elements. | Unit tests for surface connector label extraction and `canvas search` JSON snapshots. |
| LABEL-02 | Diff output must classify connector label changes separately from endpoint relinks and geometry changes. | Unit tests proving `connector_label_changed` is emitted only for label text/style changes. |
| LABEL-03 | A reviewable connector-label plan must accept connector IDs or source/target selectors and emit before/after label values without live mutation. | CLI tests for deterministic plan output and invalid selector failures. |
| LABEL-04 | Connector-label live apply must update only label fields on existing connector elements and preserve source, target, stroke, endpoints, seed, geometry, and card positions. | Apply-script tests plus reload verification against expected fields. |
| LABEL-05 | Live apply must reuse the v1.1 AFFiNE mutation safety gates: explicit live/apply flag, workspace, doc, backup dir, yes confirmation, backup-before, delta artifact, pre/post integrity, and reload verification. | `go test ./...`, gated fixture smoke plan, and proof artifact checks. |
| LABEL-06 | CLI docs, help, MCP annotations, and Printing Press patch records must describe the review-first label workflow. | Help output checks, patch record, and documentation diff. |

## Operator Workflow

```text
canvas search --from <source-card> --to <target-card>
  -> connector label plan from reviewed JSON
  -> human review of planned labels
  -> canvas apply --live with backup and proof
  -> reload verification and post-integrity
```

## Safety Rules

- Label planning is read-only.
- Label apply is mutating and must not be marked read-only for MCP.
- Empty labels are allowed only when the operator explicitly plans a removal.
- Multi-line labels are rejected until AFFiNE rendering has a tested contract for them.
- Non-ASCII labels are allowed, but tests must prove UTF-8 survives plan JSON and Y.js apply.
